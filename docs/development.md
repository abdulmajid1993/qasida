# Development & deployment

## Prerequisites

- Node.js + npm.
- `node_modules` is **not** committed; run `npm install` first.

## Commands

All from the `app/` directory:

```bash
cd app
npm install        # install dependencies
npm start          # dev server with hot reload → http://localhost:3000
npm run build      # production build → app/build/
npm test           # CRA test runner (no tests defined yet)
```

`npm run build` is the quickest check that a `.jsx` edit is syntactically
valid — a successful build means the change compiled.

## Project type

Create React App (`react-scripts` 5). See `app/package.json` for the exact
dependency versions and scripts.

## Deployment (Netlify)

Configured in `app/netlify.toml`:

```toml
[build]
  base = "app"
  command = "npm run build"
  publish = "build"
```

Netlify runs the build inside `app/` and serves `app/build/`. The `build/`
folder is also committed in the repo, but it is regenerated by `npm run build`
and should be refreshed when shipping changes.

## Deployment (GitHub Pages)

Configured via `.github/workflows/pages.yml`: on every push to `main`, it
installs dependencies in `app/`, runs `npm run build`, and publishes
`app/build` as the Pages site. `app/package.json` sets `"homepage": "."` so
CRA emits relative asset paths that work under the GitHub Pages project
subpath (e.g. `https://<user>.github.io/<repo>/`) regardless of the exact
repo name.

**One-time manual step** (can't be set via the API used to set this up):
in the repo's **Settings → Pages → Build and deployment → Source**, select
**"GitHub Actions"** (not "Deploy from a branch"). Without this, the classic
branch-based Pages builder stays active instead of this workflow, and it will
just serve the repo root as static files — since there's no `index.html`
there, that's what produces a 404.

Do **not** point Pages at the `main` branch root or `/docs` folder directly —
this repo's deployable app is CRA output inside `app/build/`, several folders
deep, which classic branch-based Pages can't reach; the Actions workflow
above builds it and uploads the right folder as the Pages artifact instead.

## Previewing locally (no Netlify needed)

You don't need to deploy to preview. CRA ships a hot-reloading dev server:

```bash
cd app
npm install      # first time only (installs node_modules)
npm start        # opens http://localhost:3000, reloads on every save
```

To preview the **production** output (what Netlify serves):

```bash
cd app
npm run build
npx serve -s build   # serves app/build/ at http://localhost:3000
```

To open it on a real phone/tablet on the same network, start `npm start` and
visit `http://<your-computer-ip>:3000` from the device. For a temporary public
link without deploying, tunnel it, e.g. `npx localtunnel --port 3000` or
`cloudflared tunnel --url http://localhost:3000`.

## Suggested verification before shipping a lyric fix

1. `cd app && npm run build` → confirms it compiles.
2. `npm start` and open the affected song → confirm the lines render correctly
   (no fused/cut lines).
3. Commit the source `.jsx` change (and, if you regenerated it, `build/`).

## Suggested verification before shipping a VISUAL change

This app is **mobile & tablet first** — see
[responsive-design.md](./responsive-design.md). Before shipping any frontend
change:

1. `npm start`, open DevTools, toggle the device toolbar.
2. Check **phone (~375px)**, **tablet (~768–1024px)**, and desktop.
3. Confirm no horizontal scroll, no clipped text, layouts stack on narrow
   screens, tap targets are ≥ ~44px, and nothing essential is hover-only.
